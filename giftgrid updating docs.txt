GiftGrid update notes
=====================

1. Trade deck stays optional
   - Upload endpoint remains (POST /api/merchant/trade-deck), but merchant_has_trade_deck / merchant_can_list return true and onboarding/qualification do not gate on a deck.

2. Everyone can autopost
   - lib/community/publishing.ts no longer requires an allowlist or developer role. Any signed-in member can publish/draft via /api/developer/community/posts and /drafts (3 posts per 24h, 4h gap, idempotent).

3. Review section
   - New listing_reviews table + GET/POST /api/listings/[id]/reviews.
   - Product pages (/market/[id]) render the Reviews section with star ratings (components/market/ListingReviews.tsx).

4. Rating on product listing
   - Each listing shows average_rating and review_count; totals update via trigger when reviews change.

5. AI rating from clicks and impressions
   - POST /api/listings/[id]/track records clicks/impressions; compute_ai_rating blends review average (70%) with click-through rate (30%) plus a review bonus; stored on merchant_listings.ai_rating.

6. Buyers can create multiple profiles on one account
   - buyer_profiles.profile_id unique constraint removed; GET/POST /api/buyer/profiles; managed in the buyer dashboard (components/buyer/BuyerProfiles.tsx).

7. Dashboard merged to community
   - Merchant dashboard moved from app/(merchant)/dashboard to app/(community)/dashboard, so it renders inside the community shell (header + CommunityNav + DashboardShell).

8. Merchant account ranking
   - New merchant_ranking view; GET /api/merchants/ranking; leaderboard shown on /merchants (components/merchant/MerchantRanking.tsx), ranked by AI rating, clicks, live listings.

9. AI chatbot knows people working with GiftGrid
   - app/api/chat/route.ts system prompt now names the founder, operations, community, and support teams.

10. AI chat bot as "GiftGrid Support" messaging everyone ~5 times daily, continuing the conversation on reply
    - New cron GET /api/cron/support-outreach (every 6h) inserts up to 5 support messages per active profile per day into support_outreach + in-app notifications. Replies continue in the existing messaging/chat UI.

11. Fiverr-style product presentation + buyer<->merchant inbox
    - Each product shows: star rating + review count (like Fiverr gig cards), a "Top rated" badge when average_rating >= 4.5 with reviews, AI rating, and a like count.
    - Buyers can like a product (POST /api/listings/[id]/like, heart count stored on like_count; GET returns totals).
    - "Message merchant" button on the product page opens (or creates) a connection with the merchant and drops the buyer into the shared inbox at /messages — same channel as the Community message center, with email + in-app notification per message.
    - Merchants without a trade deck are not hidden; the ranking board on /merchants surfaces top-rated sellers by AI rating.

12. Notification email and campaigns
    - New campaigns table + GET/POST /api/admin/campaigns to draft and send campaign emails to all/merchant/buyer/community audiences via lib/email/provider.ts.

13. Notifications on buyer brief, message, listing, community post
    - Existing queues cover buyer inquiry, product_listing, post_comment, post_like; added 'message' event type and trigger for connection messages.

14. Admin gets notified when products are listed, with time
    - Already active: queue_product_listing_email on merchant_listings insert/update to pending_review; activity digest emails render UTC timestamps.

15. Functioning CLI for autoposting
    - npm run giftgrid -- community autopost --brief "..." [--topic X] drafts via the AI and publishes in one command.

16. Full documentation
    - docs/giftgrid-update-pack.md + this file.
